# Remote Devices

Settings → Remote Devices lets you add a machine whose Claude Code or Codex CLI history lives outside this Mac. If Tailscale is installed, the form starts with **Machine**: it lists the Mac, Linux, and Windows machines on your tailnet (offline ones are greyed out, and devices you already added are left out), and picking one fills the host, System, and the device's name. The host is the machine's Tailscale IP, which works even when this Mac has Use Tailscale DNS turned off; if an alias in `~/.ssh/config` already points at that machine, the alias is used instead so its username, key, and port come along. Without Tailscale, or for any other machine, type its SSH host alias, DNS name, or IPv4 address, then pick its **System** (Linux, Mac, Windows, or Windows + WSL; new devices start on Linux). A Windows + WSL choice you already made is kept, and when Tailscale doesn't know a machine's system the form says Linux is only a guess. Tailscale can't tell plain Windows from WSL, so switch System to **Windows + WSL** yourself when the logs live in WSL. The SSH username is still yours to enter. Left blank, the field shows which account SSH will actually use (from `~/.ssh/config`, otherwise this Mac's username), and a Windows device warns when that is just this Mac's username. If you use an IP address, enter the SSH username explicitly when it differs from your Mac username; an alias can also supply the username, port, and key through `~/.ssh/config`. **Advanced SSH** contains the optional port override. **Device Name** is optional: left blank, the device is named after the picked machine (or its host), with "(WSL)" added for a WSL device so one PC's Windows and WSL devices read apart. **Add Device** first connects and checks that the folders an import reads hold Codex or Claude logs, then saves and imports the history. If the connection fails it stops with the reason (host name not found, which username was rejected, untrusted host key, missing Python) and opens **Setup Help**, which lists the setup steps and a ready-to-copy `ssh … exit` command for trusting the host key once in Terminal. If it connects but finds no logs (usually the wrong account or WSL distribution), it says so and shows the account and home folder it reached. In both cases the button becomes **Add Anyway**, so a machine that is offline right now can still be added; changing the connection details resets it. Invalid fields show their own explanation and the first invalid field receives keyboard focus. An existing device can be edited without changing its identity, and renaming one saves without reconnecting.

Choose **Windows + WSL** as the **System** when SSH connects to a Windows host and logs are in WSL. **Windows Username** is the account used for SSH. **WSL Environment** contains the optional distribution and **Linux Username**, which select the Linux home folder containing the logs. Left blank, Windows' default distribution and its default user are used. **From Windows** next to Distribution lists the host's distributions, marking the default and whether each is running; listing doesn't start any of them, and tool-owned ones such as `docker-desktop` are left out. Pick one to fill the field, or type a name. Quotapus doesn't search every distribution for logs: each distribution is its own device, so add the machine once per distribution whose logs you want. Adding the device and each import start the chosen distribution if it is stopped. **Windows** reads the Windows account's own logs. **Linux** and **Mac** run Python directly under the SSH account. Direct SSH into a WSL distribution uses **Linux**. The remote user needs Python 3 and read access to their CLI logs. Connect once in Terminal first so the SSH host key is known; Quotapus uses existing SSH keys and never stores a password.

Quotapus sends its bundled Python exporter over SSH stdin on each refresh. The script reads `~/.codex/sessions`, `~/.codex/archived_sessions`, and `~/.claude/projects` (or their supported environment-variable roots). It returns only timestamps, model names, token buckets, and deduplication IDs. Prompts, replies, credentials, and raw JSONL lines are not sent. The remote machine stores a private, incremental parsed-event cache in `~/.cache/quotapus-remote/events-v1.json`; this Mac stores only the priced daily summary and the device settings. Removing a device deletes its summary and settings on this Mac, but leaves the remote cache in place.

Quotapus refreshes connected devices alongside its normal refresh loop, all devices at once, and keeps the last good summary if a device is offline. A device gets 3 minutes to finish an import (30 seconds for the connection check when adding one); one that doesn't finish is stopped and reports a timeout, so a sleeping machine or a stuck network folder never holds up this Mac's own providers or other devices. Each device row shows a status dot, the connection and system, and one status line: importing, updated some time ago, no logs found, paused, or not imported yet. The refresh button sits on the row. A failed import says so in the status line, shows how old the saved history is, and has **Details** for the full error. A newly saved device remains listed even if its first import fails. Open its actions menu to Edit or Remove it. **Add Device** opens a separate draft; Cancel leaves saved settings unchanged. Opening Settings normally shows the device list. The SSH form appears only after Add or Edit, and an unsaved form closes when you leave Settings or close the menu panel. Optional WSL and SSH fields expand only when needed. On the dashboard, **Usage From** can show All Devices, This Mac, or one connected device. This changes the historical usage rows and the live cards, while live account quota meters remain this Mac's own values.

Remote summaries don't record which account was used. If this Mac has more than one Claude account, or more than one Codex account, Quotapus can't tell which card a device's history belongs to, so that provider's remote history is left out of the dashboard and the device row says which providers aren't counted.

The combined history is additive for local-log providers. Cursor's account-wide history is never added across devices. Avoid pointing two configured sources at copies of the same session files; for example, remove the old extra-log-root folder after migrating that device to SSH. These sources have distinct device IDs and cannot prove that copied session files are the same physical usage.

The exporter is versioned with the app. A session file that disappears mid-scan (Codex moves finished sessions into `archived_sessions`) is skipped and picked up from its new location on the next refresh; any other unreadable file still fails the import. A device with a different or missing Python runtime reports an error rather than silently producing a zero. On Windows, install Python 3 if `py -3` is unavailable. On WSL, the Windows SSH login must be able to run `wsl.exe --exec python3 -` for the intended Linux user; select a distribution or user in Settings when the default is wrong. Changing a device's connection clears its old summary before importing from the new account.

## Live speed

The dashboard's Activity card can show a device's speed next to this Mac's. A remote device's speed is worked out from the history it sent at its last import, so it only changes when the device imports again. If the last import is more than 15 minutes old, or it failed, the device shows as not live with how long ago it updated. Nothing extra is sent or run on the remote machine for this.
